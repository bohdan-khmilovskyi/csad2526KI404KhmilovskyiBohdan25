- **Студент:** Хмільовський Богдан Володимирович
- **Група:** КІ-404
- **Варіант:** 25
- **Протокол:** UART
- **Мова опису апаратури:** VHDL

## Структура проєкту

- `src/baud_generator.vhd` — генератор імпульсів із періодом, що відповідає тривалості біта UART.
- `src/uart_tx.vhd` — передавач UART.
- `src/uart_rx.vhd` — приймач UART.
- `src/uart_top.vhd` — верхній модуль, який з'єднує генератор, передавач і приймач.
- `tb/uart_tb.vhd` — тестбенч для перевірки передавання та приймання.
- `docs/` — діаграми станів і параметри реалізації.
- `reports/` — звіти синтезу, часового аналізу та версії інструментів.
- `sim/waveform.vcd` — запис часових сигналів симуляції.
- `run_sim.bat` — запуск функціональної симуляції.
- `synth.bat` — синтез і часове трасування для iCE40.

## Параметри реалізації

Формат кадру — **8N1**: один стартовий біт, вісім бітів даних (молодший біт передається першим), без парності та один стоповий біт.

Для синтезу задано системну частоту 50 МГц і швидкість UART 9600 бод. Значення `C_CLKS_PER_BIT` обчислюється цілочисельним діленням і дорівнює 5208. Розрахункова швидкість за цим значенням становить приблизно 9600,61 бод.

У тестбенчі використано частоту 1 МГц і швидкість 100 кбод, тобто 10 тактів системного сигналу на один біт. Ці параметри застосовуються лише для симуляції.

## Функціональна перевірка

Для запуску потрібен GHDL, доступний через `PATH`. Якщо GHDL встановлено в `F:\Tools\ghdl\bin`, додайте цей каталог до `PATH` у поточному сеансі PowerShell:

```powershell
$env:Path = "F:\Tools\ghdl\bin;$env:Path"
```

Із кореневої папки проєкту запустіть симуляцію:

```powershell
.\run_sim.bat
```

Тестбенч перевіряє передавання байтів `A5`, `3C`, `00` і `FF` через з'єднання TX–RX. Для кожного кадру перевіряються значення `rx_data`, імпульс `rx_valid` та відсутність `rx_error`. Після запуску часові дані записуються у `sim\waveform.vcd`; файл можна відкрити в Surfer.

## Синтез і часовий аналіз

Синтез виконано для програмної цільової конфігурації **Lattice iCE40 HX8K CT256** із частотою 50 МГц. Використано GHDL, Yosys і nextpnr-ice40. Шляхи до GHDL та OSS CAD Suite задаються на початку `synth.bat`; за потреби їх слід змінити відповідно до локального розташування інструментів.

| Показник | Результат |
|---|---:|
| Логічні комірки `ICESTORM_LC` | 141 / 7680 |
| LUT4 | 109 |
| Тригери | 64 |
| Комірки перенесення `SB_CARRY` | 24 |
| Максимальна частота після трасування | 141,92 МГц |

Файл PCF із призначенням виводів не використовувався, тому контакти розміщувалися автоматично. Фізичну FPGA-плату не підключали. Наведені показники стосуються програмного синтезу та трасування для обраної конфігурації.

## Обмеження реалізації

- Вхід `rx_serial` не проходить через окремий двотригерний синхронізатор.
- `tx_start` потрібно подавати однотактним імпульсом лише за `tx_busy = '0'`. Оскільки цей сигнал перезапускає лічильник генератора швидкості, запит під час активного кадру може змінити тривалість біта.
- Тестбенч перевіряє коректні кадри у з'єднанні TX–RX. Окремі перевірки хибного стартового та некоректного стопового біта не реалізовані.
