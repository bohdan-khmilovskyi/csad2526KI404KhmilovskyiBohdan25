# АПКС — лабораторна робота №3, варіант 25

**Завдання:** UART, мова опису апаратури VHDL.

## Склад проєкту

- `src/baud_generator.vhd` — генератор імпульсів швидкості UART.
- `src/uart_tx.vhd` — передавач UART.
- `src/uart_rx.vhd` — приймач UART.
- `src/uart_top.vhd` — верхній модуль, що об'єднує TX та RX.
- `tb/uart_tb.vhd` — самоперевірний тестбенч з loopback.
- `docs/` — FSM-діаграми та параметри протоколу.
- `run_sim.bat` — аналіз VHDL, elaboration, запуск симуляції та створення VCD.

## Прийняті параметри

Методичка визначає протокол UART та VHDL, але не задає системну частоту, швидкість передачі або формат кадру. Для базової моделі прийнято **8N1**:

- 1 стартовий біт (логічний 0);
- 8 бітів даних, молодший біт передається першим;
- без біта парності;
- 1 стоповий біт (логічна 1).

Параметри верхнього модуля за замовчуванням: `G_CLK_FREQ_HZ = 50_000_000`, `G_BAUD_RATE = 9_600`. Це початкові проєктні значення, а не підтверджені параметри конкретної плати ПЛІС. Перед апаратним синтезом їх потрібно узгодити з викладачем/моделлю ПЛІС.

У тестбенчі використано прискорений симуляційний режим: 1 МГц / 100 кбод = 10 тактів на біт. Це не апаратна конфігурація плати.

## Налаштування GHDL у PowerShell

Якщо `ghdl --version` працює лише з каталогу `bin`, додайте цей каталог у PATH поточного вікна PowerShell. Підставте фактичний шлях до своєї папки `bin`:

```powershell
$env:Path += ";F:\ШЛЯХ\ДО\ghdl-mcode-6.0.0-mingw64\bin"
ghdl --version
```

Після цього відкрийте папку проєкту у Провіднику та запустіть `run_sim.bat`.

## Запуск симуляції

1. Переконайтеся, що команда `ghdl --version` працює в PowerShell.
2. Запустіть `run_sim.bat`.
3. Скрипт проаналізує VHDL-файли, створить тестовий виконуваний модуль і запустить перевірки.
4. У разі успіху буде створено `sim/waveform.vcd`.
5. У Surfer відкрийте `sim/waveform.vcd` через `File → Open` або перетягніть файл у вікно програми.

У тестбенчі перевіряються байти `A5`, `3C`, `00`, `FF`. Усі перевірки виконуються через VHDL assertions.

## Важливо щодо синтезу

GHDL використовується для симуляції VHDL і не замінює інструмент синтезу для цільової ПЛІС. Для отримання звіту LUT/Flip-Flops та Fmax потрібна модель/родина ПЛІС і відповідний інструмент синтезу (наприклад, Quartus або Vivado). Цільова ПЛІС у методичці не вказана — її необхідно уточнити окремо.
