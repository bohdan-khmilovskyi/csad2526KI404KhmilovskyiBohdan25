# Архітектура AI-агента

## 1. Які проблеми вирішує агент

Агент `build-engineer` автоматизує створення відтворюваного кросплатформного C++ Hello World проєкту та перевірку його основних складових. Він допомагає уникнути ручного налаштування початкової структури, CMake, GoogleTest/CTest і GitHub Actions для Windows, Linux та macOS.

Інструкції визначають очікувані файли й команди перевірки, а також правила безпечної роботи з наявним вмістом: спочатку перевіряти файли, не перезаписувати конфліктні дані та повідомляти про помилки замість того, щоб удавати успішне завершення.

## 2. Skills та їхня відповідальність

| Skill | Відповідальність |
|---|---|
| `project-scaffold` | Створення початкових файлів C++: `src/main.cpp`, `src/add.h`, `src/add.cpp`, каталогів для тестів і документації та README за потреби. |
| `build-and-test` | Налаштування CMake і C++17, бібліотеки `add_lib`, виконуваного файла `hello`, GoogleTest/CTest, тесту `BasicAddition` і скриптів `ci.sh` та `ci.bat`. |
| `github-actions` | Створення workflow для Linux, Windows і macOS, який запускає наявні CI-скрипти та завантажує артефакт збірки. |

## 3. Команди для користувача

| Команда | Призначення |
|---|---|
| `git-init` | Перевірка Git-репозиторію та створення або доповнення `.gitignore`. |
| `create-project` | Створення початкового каркаса C++ проєкту. |
| `create-build` | Налаштування збирання, тестів і платформних CI-скриптів. |
| `create-actions` | Налаштування GitHub Actions workflow для трьох платформ. |
| `check` | Перевірка структури, збірки, тестів, workflow та правил Git-ігнорування в режимі лише для читання, крім тимчасових результатів у дозволеному `build/`. |
| `init` | Послідовний запуск усіх кроків із перевіркою кожного результату. |

## 4. Дані між етапами

Потік проєктних даних відбувається послідовно:

1. **`project_name` → `src/`**: команда `create-project` використовує назву проєкту (типово `hello`) і параметр мови `C++`, щоб визначити каркас та створити `src/main.cpp`, `src/add.h` і `src/add.cpp`. `main.cpp` використовує `add`.
2. **`src/` → `CMakeLists.txt`**: команда `create-build` бере ці вихідні файли як вхідні дані. CMake описує бібліотеку `add_lib`, виконуваний файл `hello` і тестову ціль GoogleTest, зокрема тест `BasicAddition`.
3. **`CMakeLists.txt` → `ci.sh` / `ci.bat`**: CI-скрипти конфігурують і збирають CMake-проєкт, запускають CTest і копіюють зібраний виконуваний файл до `dist/`. Shell-скрипт призначений для Linux/macOS, batch-скрипт — для Windows.
4. **`ci.sh` / `ci.bat` → `ci.yml`**: workflow GitHub Actions запускає відповідний скрипт на кожній платформі й завантажує вміст `dist/` як артефакт. Сам workflow не виконує команди CMake чи CTest напряму.

## 5. Обробка помилок оркестратором `init`

Оркестратор `init` виконує кроки у фіксованій послідовності: `git-init`, `create-project`, `create-build`, `create-actions`, `check`. Він перевіряє результат поточного кроку перед переходом до наступного. Якщо prompt відсутній, файл конфліктує з наявним вмістом, команда завершується помилкою або обов’язкова перевірка не проходить, оркестратор зупиняється, повідомляє крок і причину та вказує, що потрібно виправити. Наступні кроки не запускаються. Успіх усього процесу оголошується лише після явного `Статус: PASSED` від `check`.

## 6. Відповідність файлів їхнім ролям

| Роль | Розташування | Приклади |
|---|---|---|
| Agent | `.github/agents/` | `build-engineer.agent.md` |
| Skills | `.github/skills/<skill-name>/` | `project-scaffold/SKILL.md`, `build-and-test/SKILL.md`, `github-actions/SKILL.md` |
| Commands (prompt files) | `.github/prompts/` | `git-init.prompt.md`, `create-project.prompt.md`, `create-build.prompt.md`, `create-actions.prompt.md`, `check.prompt.md`, `init.prompt.md` |

## 7. Формат VS Code Copilot

Цей репозиторій використовує формат налаштувань **VS Code Copilot**: custom agents (`.agent.md`), prompt files (`.prompt.md`) і agent skills (`SKILL.md`). Ці файли задають ролі агента, команди для запуску та спеціалізовані інструкції, які завантажуються для відповідних завдань.
