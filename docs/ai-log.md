	# Ініціалізація проєкту

	Ти — оркестратор. Виконуй наведені кроки **строго по порядку**. Для кожного кроку прочитай повний вміст відповідного prompt-файлу та виконай його інструкції, а не просто переказуй їх. Не переходь до наступного кроку, доки поточний не завершено й не перевірено.

	## Передумови

	- Переконайся, що поточний каталог є коренем Git-репозиторію.
	- Перевір стан робочого дерева перед початком. Не перезаписуй наявні зміни користувача, не видаляй файли та не переписуй Git-історію.
	- До початку роботи перевір існування всіх п’яти prompt-файлів зі списку кроків. Якщо файл відсутній або недоступний для читання, зупинись і повідом про це.
	- Дотримуйся обмежень кожного prompt. Зокрема, крок `check` є лише для читання і не може виправляти виявлені проблеми.

	## Дії

	Виконуй кроки в такому незмінному порядку:

	1. Прочитай і виконай [git-init](./git-init.prompt.md).
	2. Якщо крок 1 завершився без помилок, перевір створений або доповнений `.gitignore`, результат `git status` та всі перевірки, визначені prompt. Потім прочитай і виконай [create-project](./create-project.prompt.md).
	3. Якщо крок 2 завершився без помилок, перевір результати та перевірки, визначені prompt. Потім прочитай і виконай [create-build](./create-build.prompt.md).
	4. Якщо крок 3 завершився без помилок, перевір результати та перевірки, визначені prompt. Потім прочитай і виконай [create-actions](./create-actions.prompt.md).
	5. Якщо крок 4 завершився без помилок, перевір результати та перевірки, визначені prompt. Потім прочитай і виконай [check](./check.prompt.md) у його режимі лише для читання.

	Після кожного кроку зафіксуй його статус і фактично створені або змінені файли. Якщо крок має помилку, невиконану обов’язкову перевірку, конфлікт файлів або не може підтвердити завершення, негайно зупинись: не запускай жоден наступний крок. На кроці 5 успіхом вважай виключно явний результат `Статус: PASSED` від `check`; будь-який `FAIL`, пропуск перевірки або відсутній статус означає зупинку без оголошення успіху.

	## Очікувані файли

	Залежно від успішно завершених кроків, очікуваними результатами можуть бути:

	- `.gitignore`
	- `src/main.cpp`, `src/add.h`, `src/add.cpp`
	- `README.md`, якщо його не було
	- каталоги `tests/` і `docs/`, якщо їх не було
	- `CMakeLists.txt`, `tests/test_basic.cpp`, `ci.sh`, `ci.bat`
	- `.github/workflows/ci.yml`
	- тимчасові результати збирання в `build/` та артефакт у `dist/`, якщо цього вимагають відповідні кроки

	Це перелік можливих результатів, а не дозвіл створювати їх поза відповідним кроком. Не створюй додаткових файлів і не видаляй наявні. Фіксуй тільки ті файли, які фактично створено або змінено під час кожного кроку.

	## Повідомлення про помилку

	Якщо будь-який крок завершується помилкою:

	1. Зупини виконання; не запускай наступні кроки й не намагайся автоматично обійти помилку.
	2. Виведи звіт із назвою/номером кроку, конкретною причиною та тим, що потрібно виправити для повторного запуску.
	3. У фінальній таблиці познач завершений невдалий крок як `FAILED`, а кроки, які не запускалися, як `NOT RUN`.
	4. Не оголошуй успіх і не використовуй статус `PASSED`, якщо крок `check` не завершився явним `Статус: PASSED`.

	## Ідемпотентність

	- Дотримуйся правил безпечної повторної роботи та ідемпотентності кожного крокового prompt.
	- Перед будь-яким записом перевіряй наявний вміст; зберігай сумісні файли й не додавай дубльованих секцій, цілей, команд чи правил.
	- Не видаляй файли, не перезаписуй наявний вміст без перевірки й не змінюй незв’язані файли.
	- Не запускай кроки повторно в межах одного проходу, щоб приховати невдалу перевірку.

	## Фінальний звіт

	Після зупинки через помилку або після завершення всіх кроків виведи таблицю:

	| Крок | Статус | Створені/змінені файли |
	|------|--------|-------------------------|
	| `git-init` | `PASSED` / `FAILED` / `NOT RUN` | Список фактичних шляхів або `—` |
	| `create-project` | `PASSED` / `FAILED` / `NOT RUN` | Список фактичних шляхів або `—` |
	| `create-build` | `PASSED` / `FAILED` / `NOT RUN` | Список фактичних шляхів або `—` |
	| `create-actions` | `PASSED` / `FAILED` / `NOT RUN` | Список фактичних шляхів або `—` |
	| `check` | `PASSED` / `FAILED` / `NOT RUN` | `—` (лише читання) |

	Називай весь процес успішним лише тоді, коли всі попередні кроки завершені без помилок, а `check` явно вивів `Статус: PASSED`.
